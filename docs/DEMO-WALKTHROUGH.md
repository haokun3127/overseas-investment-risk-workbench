# 工作台演示顺序

入口：https://47.108.51.138/rag/ 。管理员密码沿用部署时的独立密码。

所有示例都是虚构资料，不是真实新闻或投资结论。

1. 登录后看风险总览，选择“演示数据”，展示分类、红橙黄等级与待复核列表。
2. 打开“API演示：港口拥堵导致原料断供风险”对应风险，展示实际模型生成的摘要、潜在影响、建议及连续原文引用。分析记录显示 gpt-6.1-sol / 外部 API。
3. 在资料管理打开“API演示：例行培训不构成风险事件”，点击查看原文，查看分析版本与非风险结论，说明系统不会把每条资料都判为风险。
4. 打开“API演示：缺少原始证据需补充资料”，展示资料不足的判断，不补写未知事实。
5. 在分析任务查看三条 API 演示的真实任务记录。在模型与规则查看模型名称、Responses 协议、low 推理强度和响应存储关闭。
6. 展示一条内置案例的业务复核、风险台账导出和风险简报。内置案例的分析记录明确显示“未调用模型”。

内置展示案例：供电中断、清关要求调整、港口班次减少、排班沟通争议。
合成 API 示例：港口拥堵、例行培训、缺少原始证据。

演示数据在真实资料筛选中排除，内置和合成示例均不从正常资料队列重复发送。现场需要演示新任务时，应另行录入清楚标注“虚构”的测试内容，并明确授权外部分析；不要把演示结果用于真实投资决策。

演示规则仅用于虚构资料验证，版本 demo-validation-v1。正式使用前应按业务标准修改并确认。

重复准备演示的离线命令（先停止工作台服务；此命令会调用模型，产生 API 用量）：

```sh
cd /opt/rag-workbench/current
runuser -u rag-workbench -- env PYTHONDONTWRITEBYTECODE=1 /opt/rag-workbench/venv/bin/python -m scripts.seed_presentation --env-file /etc/rag-workbench/workbench.env --analyze --allow-external-demo
```

脚本按资料摘要去重，已有同模型成功结果时跳过，不覆盖历史分析。
