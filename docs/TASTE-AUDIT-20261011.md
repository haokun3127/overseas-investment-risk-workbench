# Taste Skill 前端审查

审查来源：https://github.com/Leonxlnx/taste-skill 。读取主技能与 `skills/redesign-skill/SKILL.md`；主技能v2明确排除后台、数据表格和多步产品UI，因此本次采用同仓库的现有项目审查规范，结合业务工作台实际需求。没有安装脚本、修改业务代码或部署新版本。

审查对象：当前线上风险总览、风险事件列表与核验面板，桌面1440px及手机390px。页面截图保存在 `taste-audit-20261011/`。旧标签初始加载了上一版资源，刷新后按当前分布图默认版本重新检查。

## 优先问题与改法

1. **优先修正演示提示。** API合成演示案例的核验面板显示“虚构演示案例，未调用模型”，与此前实际模型调用记录冲突。`web/workspace.js` 直接使用 `e.demo` 决定这句提示，混淆了资料真实性与分析方式。应分别表达“虚构资料”及实际分析模型/模式，未知调用方式时只声明资料为虚构，不能推断未调用模型。
2. **手机首屏未展示事件。** 页面标题、三项操作、数据范围及完整筛选表单占满390×844首屏。默认保留搜索及“待复核/高风险”等快捷入口，将日期、分类等高级条件折叠到可展开区域，保留已选条件提示。导出和简报可进入更多操作，导入保持可访问但降低本页强调程度。
3. **桌面空核验面板占用较多宽度。** 未选事件时仍预留约三分之一列宽及大面积空白。建议未选时列表占满内容区，点击核验后出现侧面板；关闭面板恢复列表。保留筛选、选中行和复核草稿。
4. **部分文字偏小且对比不足。** 筛选辅助说明为11px、颜色rgb(132,144,163)，白底对比约3.23:1；待复核标签为11px、rgb(113,128,150)配rgb(240,243,248)底色，对比约3.61:1。普通小字应达到4.5:1，建议辅助正文至少12px并加深颜色；主要事件标题和阅读正文保持清晰层级。风险色仍用于等级语义。
5. **复核操作距离证据较远。** 当前面板按摘要、影响、建议、引用、表单顺序长距离滚动。建议面板内使用“判断 / 依据 / 复核”定位入口，底部固定保存区，允许一键下一条待复核事件，保存成功反馈紧邻操作。
6. **首页首屏可更紧凑。** 保留分布图默认展示及点击筛选，把标题、业务范围、数据范围及演示提示组织得更紧凑，压缩统计区高度，使图表主体在首屏呈现更多内容。分布图保持业务图形，避免为了装饰加入营销图片和高强度动效。

## 设计取向

继续使用蓝白业务工作台、中文系统字体及现有路由。统一字号、灰阶、边框、阴影与圆角层级，减少嵌套卡片。优先提高识别事件、定位证据和保存复核的速度，不迁移框架、不改造为营销网站。建议实施顺序：提示准确性、手机筛选、桌面列表/面板、对比和排版、复核操作、首页间距。

本次是审查建议，不是实现验收；未覆盖真实手机、完整错误流程或大规模数据性能。
