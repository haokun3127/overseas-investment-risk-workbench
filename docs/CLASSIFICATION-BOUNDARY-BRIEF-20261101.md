# 分类边界合并说明

本轮停止继续叠加个案提示，按客户已给案例说明将剩余问题归为分类规范的表达缺口。
目标不变：19例风险判定、三级集合及分级一致；不硬编码公司名、案例ID或期望答案。

## 证据与冲突

在完整向量与知识召回后的v7实测中，19例判定与分级均与参考相符，仅一例生产配额事项的三级不同。
客户案例说明将现有企业的产量行政配置归在政治风险研究范围，但现有三级表没有精确覆盖项，要求对不上。
实际召回的企业公告说明初始生产销售额度通知、后续调整申请及维护停产后复采，没有直接列出本案制定或修订一项普遍适用法律规则。

原规则“法律政策变动”的简短解释过宽，易将一切行政决定和数量变化都包括进去。
这不是应该用案例ID覆盖输出的问题，也不是应该删除实际公告的问题。

## 合并后的业务口径

- 法律政策变动须有法律、法规或普遍适用的监管规则被制定、修改、废止或新适用的直接事实；只见行政决定、年度指标和个案额度变化，不自动满足。
- 准入审批限制须有进入市场、新投资设立、取得初始经营资格等准入审批事实；现有经营者按原制度申请年度产量、销售数量或作业计划，不因也叫“审批”就自动归入。
- 两项条件都没有直接证据，而经营损害已发生时，应保留risk、等级和事实引文，三级标为对不上，待人工扩充体系；不能为了凑类别猜测新法律或初始准入被拒。
- 若同一资料另有实际法律修订、市场准入限制的直接事实，仍按其独立机制归类，不使用配额关键词一刀切屏蔽其他类别。

以上属于本客户分类体系的边界澄清，不是所有法律/投资业务的通用法律结论。
将规范置于规则数据层并保存版本；向量只作为检索提示，不能成为范围更窄的另一套规范。

## 下一步验证

先生成未含参考标签的相同真实RAG输入，检查规则版本、45个合法类别和对不上出口；
再全量复跑，而非只重试该个案。保留每次差异，不只报告最好一次。

## v8复跑后的结构诊断

首轮19/19；同版第二轮17/19。一个任务因引文不是连续原文，补正仍抄写失真而失败；
另一个同一事项的两个独立政策指标分别评成lv3和lv4，客户参考对该事项作整体lv3评价。
不通过增加公司名或答案映射解决。

- 引用补正改为选择程序编号的原文句段，程序只从已有原文重建引文；仍只允许一次补正，仍要求S直接证据，仍禁止改分类等级。
- 同一核心事项按共同的实际经营影响定级，拆分指标不应拆割或抹去该共同影响；真正独立的事项仍分别评价。模型自行判断，不用最大等级覆盖原输出。
- 这两项改变分别用边界测试和完整两轮实际模型运行核验。不得将v8最好一轮当作稳定通过。

因此当前诊断是分级/主体适用口径不足以唯一复现参考，而不是继续按案例增加另一条提示。

## 用户要求继续尽量复现后的有限修正

并区分有限和解整改与有证据的持续运营影响。仍由模型根据原文判断，不对结果作固定类别或等级替换。
