# 客户案例验收与隔离验证

验收集含19例。对照风险判定、三级指标集合与预警口径；不将摘要逐字复制视作分析能力。
16例风险需校验各指标等级；3例非风险不创建风险事件，客户绿色参考对应系统non_risk。

原始资料、参考答案、模型输入和模型输出分离，留在私有工作目录，不提交本仓库。
未向模型发送期望分类或等级，未使用公司名/案例ID到答案的映射，未用参考答案覆盖实际输出。
本批已经用于诊断与规则澄清，是开发集；同批复测不等于独立盲测，不保证未来数据100%一致。

## 代码变化

- 支持证据明确但现有45个三级没有精确覆盖时输出“对不上”，仍保留等级、原文和人工复核。
- 同标题、同引文支持多个不同指标时按类别保留，避免去重丢失另一机制。
- 向量预选是focus_categories检索提示，不能删除其余合法指标；覆盖统计与查询使用同一focus。
- 将普遍规范变更与个案年度数量核定的分类边界放入有版本的规则数据，禁止按关键词硬套。
- 明确地域、事实时点、核心事项与后果的边界，以及共同事项的整体影响定级。
- 引用只允许一次补正：模型选择程序编号的连续原文句段，程序重建原文；
  补正不能修改判定、分类、等级，未知句段、越权字段和没有直接来源的结果均拒绝保存。
- 明确企业腐败被处罚所需的责任主体证据，区分涉案关联、交易历史与实际经营损害，防止无证据扩张分类或等级。
- 正常向量推理与索引默认批量由16降为2，保持单线程；不再仅靠私有测试参数控制批量。
- 向量与逐段两条路径都保留全部已提供的公司业务字段，省略内部ID、权限与更新时间；投资规模、股权、用工、供应链及许可不再因向量路径而丢失。

## 资源与来源

本地Windows隔离环境完成45指标、361知识片段的实际向量索引与19例Worker准备流程。
模型离线缓存、单线程、默认batch=2，Windows Job Object硬上限1536MB。
正常默认参数冷启动重建45指标和361知识片段完成，峰值709.3MB、耗时29.72秒；冷库生成的19例检索输入与热库逐字节相同。
19例事实片段均完整送出；14例召回实际参考原文，5例仅有公司档案知识。
52个独立参考URL中32个取得可分析文本，20个失败或为动态模板；访问失败不绕过TLS、不冒充已读。
PDF提取最多前300页，正文长度有约120k字符阈值，不将长文档视为全本阅读。

真实模型半程使用本地准备好的检索输入，在服务器独立进程调用原有外部API；
每进程512MB内存上限、swap=0、CPU25%。不在生产服务加载额外向量模型。
该验证是本地向量检索加远端API的分段实际链路，不宣称服务器已承载完整向量负载。

## 网站数据与部署边界

用户已明确授权旧业务数据不再使用。正式业务数据已替换为19家公司、19份案例事实、
19次实际分析、17条风险、52个来源入口；连同档案与原文分卷共80份资料。
32个抓取成功来源未做AI相关性判定，相关字段保持NULL；所有来源计划关闭，资料未授权重新外发。
账号保留，旧库、附件与向量状态有服务器私有可回退备份，未不可恢复地删除。

正式current仍为20261029-frontend-harden；候选分析代码未部署。网站当前是隔离实际输出回放，
不能把网站数据已替换说成服务器分析程序已升级。当前采用完整检索v11真实回放，两轮均19/19，40处引文与原文相符（其中5处为知识库引文）；先前v8/v9差异仍全部披露，不将同一开发集上的匹配率宣传为新样本正确率。
离线正式后端API校验、原文引用校验和8个主要页面及2个手机视口检查通过。

两轮实测、失败明细、规则/模型/提示词版本、输入摘要与资源记录均保存在私有目录，
网站数据替换、原账号保留、引用检查、真实向量冷启动与两轮模型复现均已完成；最终验收以v11完整两轮、175项代码检查及独立审计为准。
20个无法取得正文的来源和PDF提取上限如实保留，未宣称全链接/全本已读；服务器只展示回放，候选分析代码及高推理参数未替换线上程序。此部署边界遵从用户“服务器可以不做，但是数据也要改”的选择。
